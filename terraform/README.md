# Fortaleza on AWS

Serverless and (almost) free at hobby traffic:

```
browser ──► CloudFront ──┬─ /*      ──► S3 (private, Origin Access Control)   Vue site
                         └─ /api/*  ──► Lambda Function URL (.NET 10, arm64)  Fortaleza.Api
```

* The API keeps **no server state**. Every request carries the player's track (the commands so far),
  the Lambda rebuilds the game by replaying it and runs the new command. Any Lambda instance can answer.
* The Lambda URL is technically public, but `Fortaleza.Api` only answers requests that carry the
  `X-Origin-Verify` secret that CloudFront adds (a random value generated by Terraform).
* CloudFront gives HTTPS, caching and a single origin, so the browser needs no CORS.

## Prerequisites

* Terraform >= 1.6, .NET 10 SDK, Node 20+, and AWS credentials in the environment
  (`aws configure`, SSO, or `AWS_PROFILE`).

## Deploy

```powershell
./terraform/deploy.ps1            # PowerShell 7
```

```bash
./terraform/deploy.sh             # Linux, macOS, Git Bash
```

The script builds the site into `terraform/build/site`, publishes the API into
`terraform/build/publish`, then runs `terraform init` and `terraform apply`. Add `-AutoApprove`
(`--auto-approve` in bash) to skip the confirmation. The last line printed is the site URL.
Re-running it deploys updates: Terraform re-zips the API, re-uploads the changed site files, and
`index.html` is served with `no-cache`, so no CloudFront invalidation is needed.

Tear everything down with `./terraform/deploy.ps1 -Destroy` (or `./deploy.sh --destroy`).

## Options

Copy `terraform.tfvars.example` to `terraform.tfvars`:

| Variable | Purpose |
|---|---|
| `reserved_concurrency` | Caps parallel Lambda executions (cost guard). Brand-new accounts may need a quota increase first. |
| `budget_email`, `budget_limit_usd` | Email alert at 80% of a monthly budget. |
| `domain_name`, `certificate_arn` | Custom domain. The ACM certificate must be in `us-east-1`; then create a DNS CNAME to the `cloudfront_domain_name` output. |
| `lambda_memory_mb` | 512 by default; more memory only shortens cold starts. |

## Custom domain

No Terraform code changes are needed; the distribution already supports it through two variables:

1. **Request a certificate** in ACM **in `us-east-1`** (CloudFront only accepts certificates from that region)
   for your domain, validate it with the DNS record ACM shows you, and wait until its status is *Issued*.
2. **Set the variables** in `terraform.tfvars`:

   ```hcl
   domain_name     = "fortaleza.example.com"
   certificate_arn = "arn:aws:acm:us-east-1:123456789012:certificate/..."
   ```

   Both must be set together; Terraform refuses to apply if only one is.
3. **Apply** (`./deploy.ps1`). CloudFront now answers to that host name and `site_url` shows it.
4. **Create the DNS record** pointing the domain at the `cloudfront_domain_name` output:
   a `CNAME` for a subdomain, or an `ALIAS`/`ANAME` (Route 53: an alias A/AAAA record) for an apex domain.

The API needs nothing else: browser and API share one origin, so there is no CORS to configure.

## Cost

Inside the AWS free tier (1M Lambda requests and 1 TB CloudFront transfer per month) this costs about
$0. Beyond it: Lambda is roughly $0.20 per million requests plus compute time, and a game command
costs a few milliseconds. The S3 bucket holds under 1 MB.

## State

Terraform state is local (`terraform.tfstate`, git-ignored). For a team, add an S3 backend in
`versions.tf`:

```hcl
terraform {
  backend "s3" {
    bucket = "my-terraform-state"
    key    = "fortaleza/terraform.tfstate"
    region = "us-east-1"
  }
}
```

## Notes

* The runtime is `dotnet10`. If your region does not offer it yet, change `runtime` in `main.tf` and
  the `TargetFramework`s accordingly.
* The deploy builds with `PublishReadyToRun`, which shortens the cold start.
* Local development is unchanged: `dotnet run --project src/Fortaleza.Api` (serves `wwwroot` when the
  site has been built) or `npm run dev` in `src/Fortaleza.Web`, which proxies `/api` to port 5080.
